ONE-TIME ADMINISTRATOR SETUP

GitHub Pages + private cloud data

  1. Create a dedicated Supabase project in an institution-approved region. Apply supabase/schema.sql and its access tests.
  2. Invite accounts in Supabase Authentication. Add the first administrator with supabase/bootstrap_admin.sql. Only listed, active members can read or write workspace data.
  3. Set the project URL and public publishable key in site/config.js. Never put a secret key, service-role key or GitHub token in the webpage.
  4. Deploy only the site/ directory to GitHub Pages using the included workflow. Keep image data and ROI ZIPs out of the Git repository.
  5. Configure the site URL and allowed authentication redirects in Supabase. Test with two accounts and a signed-out browser before uploading experiments.

Without this setup, this page is a local preview—not a live collaboration service. This package has not created a public site or uploaded your data.

See README_zh.md and SECURITY.md in the project package. Cloud quotas, account plan and institutional data policy must be checked by the project owner.
